#Fully parallel sort; I had to edit the whole thing, which was quite hard and tricky; now it does the scatter part forwardly instead of backwardly. I profiled it with hotspot and I got this, regarding where does the parallel function spends its time 

### Phase 1: counting loop

| Line   | Code                                 | Self time |
|--------|--------------------------------------|-----------|

count gets better with multithreading, prefix grows with threads number but is a very small share of the time anyway, alloc is steady, and scatter significantly improve with more threads. 
Alloc takes more than half of each run, which makes sense as the vector used are really big, but I need to think of a better way
